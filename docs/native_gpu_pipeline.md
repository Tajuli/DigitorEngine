# Native GPU pipeline (v3.0.0)

The v3 renderer introduces an internal `IRenderBackend::render_rgba8` submission
contract without changing the public C ABI. A pass accepts an optional tightly
packed RGBA8 texture and returns the rendered RGBA8 target used by preview.

## Backend implementation

* **OpenGL ES 3** creates a framebuffer, compiles a fullscreen-triangle vertex
  shader and texture-sampling copy fragment shader, binds the input texture,
  draws, synchronizes with `glFinish`, and reads the framebuffer for preview.
  An empty input records a native clear pass.
* **Metal** creates a command queue and command buffer, a render-target texture,
  records a clear render pass, waits for completion, and reads the completed
  texture. RGBA input can be uploaded into the target.
* **CPU** implements the identical clear/copy contract and remains the portable
  reference and fallback.

Vulkan and D3D12 currently retain their v2 native allocation paths. Their full
graphics pipeline and validation qualification remain blocked on dedicated
platform runners; they must not be reported as v3 rendering-complete.

## Preview and export

`SharedRenderer` asks the initialized GPU backend for the completed native frame
and converts that readback to the existing `VideoFrame` representation. This
keeps `PreviewRenderer` source-compatible. Export is intentionally unchanged and
is not part of v3.

## Validation

```sh
cmake -S . -B build -DDIGITOR_ENABLE_FFMPEG=OFF
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Platform CI must additionally run GLES under an EGL debug context and Metal with
API Validation enabled. Vulkan validation layers and the D3D12 debug layer remain
required before those backends can be marked complete.

## Canonical preview pixel contract

Native preview upload and readback uses **RGBA8_UNORM** in `R, G, B, A` byte
order. The origin is the top-left, rows proceed from top to bottom, and returned
rows are tightly packed at exactly `width * 4` bytes (`width * height * 4`
bytes total). A clear produces opaque black `(0, 0, 0, 255)`. Supplied alpha
is preserved; alpha is opaque when pixels are generated by the clear operation.
Backend-specific row padding and BGRA storage must never escape through this
shared contract.
